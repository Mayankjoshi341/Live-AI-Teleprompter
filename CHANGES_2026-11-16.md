# Fixes — 16 November 2026

## Problems corrected

1. **Transcript contrast:** the microphone iframe now uses explicit high-contrast colors instead of an undefined theme variable that fell back to dark text against a dark panel.
2. **No answer after Stop:** the component previously sent `JSON.stringify(payload)` while declaring `dataType: "json"`. Streamlit stores the JSON value it receives as-is; the Python app expected a dictionary, so a string payload was ignored. The component now sends a native JSON object (`value: payload`) and Python also accepts legacy JSON-string payloads.
3. **Microphone permission:** Start now explicitly calls `navigator.mediaDevices.getUserMedia()` from the user click to invoke the browser permission prompt, checks HTTPS/secure-context requirements, and reports actionable permission errors.
4. **Mobile fallback:** the app records an audio backup with `MediaRecorder`. If Web Speech recognition is unavailable or fails to produce a final transcript, the audio is sent to Gemini 3.5 Transcribe after Stop.
5. **Answer fallback:** when no uploaded notes are present or no note matches, the app can still generate a general Gemini answer and labels it as general knowledge rather than document-grounded.
6. **Component sizing:** the component frame height is increased so the transcript and help text are not clipped.

## Run

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

For phone microphone access, open the app over **HTTPS**. Plain HTTP LAN addresses such as `http://192.168.x.x:8501` are not secure contexts and browsers normally block microphone capture. On the first tap of Start, choose Allow when prompted. If previously blocked, open the browser site's permissions and set Microphone to Allow, then reload.
